# 前备知识（写给生信背景的队友）

> ⚠️ 这份文档假设读者**没做过机器学习竞赛**，但**做过生信数据分析**。
> 所以不讲统计基础（那些你本来就会），专讲**这个比赛特有、而且我一直在用的概念**。
>
> 阅读顺序建议：§1 对照表先扫一眼建立映射，然后按需跳到后面。

---

## §0 先说结论：你已经会的比你以为的多

生信分析和这个比赛，**底层是同一件事**：从高维、有噪音、样本量有限的数据里找规律，
并且**证明你找到的不是假象**。

| 你天天在做的事 | 在这里是什么 |
|---|---|
| 批次效应校正 | **分布偏移（distribution shift）** |
| 差异表达分析选基因 | **特征选择** |
| 用通路解释富集到的一堆基因 | **特征重要性 + 解释** |
| 留一法 / 分折验证分类器 | **交叉验证** |
| 担心过拟合（细胞数少、基因数多） | **过拟合**（一模一样的问题） |
| GWAS 的多重检验校正 | **统计显著性 / 假发现** |
| 用多个 marker 而不是一个基因判定细胞类型 | **集成学习** |

**真正新的是三块**：① 一些具体方法的**名字和套路**；② **工程化**（怎么让代码可复现）；③ **竞赛文化**（和发论文很不一样）。下面逐个讲。

## §1 生信 ↔ 机器学习竞赛 概念对照表

| 生信里的说法 | 这里的说法 | 差别 |
|---|---|---|
| 批次效应 | **分布偏移 / domain shift** | 本质同一个问题：训练数据的规律到了新数据上不成立 |
| 样本来源不同（不同中心/平台） | **协变量偏移** | 特征分布变了，但"特征→结果"的规律没变 |
| 患病率不同（病例对照比例变了） | **标签偏移** | 结果的比例变了 |
| 机制本身变了（新变种） | **概念偏移** | 规律本身变了，**这个最难救** |
| 分折验证 / 留一法 | **交叉验证（CV）** | 一样的东西 |
| 数据被污染了 | **数据泄漏（leakage）** | 见 §3.2，比你想的更隐蔽 |
| 通路富集把基因归成模块 | **特征分组 / 特征重要性聚类** | 一样的思路 |
| Knockout / 敲除实验 | **消融实验（ablation）** | 见 §3.4，思路完全一样 |
| 用多个证据交叉验证 | **集成 / 融合** | 见 §4 |
| 文献里的"候选靶点" | **候选 / 关联**（不是因果） | 措辞纪律也一样 |

## §2 模型层：梯度提升树（GBDT）

### 2.1 它是什么

**一句话**：一堆"很笨的决策树"接力，每棵树专门纠正前一棵树的错误，最后加起来。

**你熟悉的类比**：像**迭代式的差异分析**——先找一个粗糙的分类规则，看它在哪些样本上错，
然后专门针对这些错样本再找一个规则，如此反复几百次。

### 2.2 为什么它在表格数据上比深度学习强

这有篇很有名的论文专门研究过（`grinsztajn2022why`，我核实过原文）。三条原因：

1. **对无用特征不敏感** —— 你给它 5000 个基因，其中 4900 个没用，它也不会崩。
   神经网络会被这些噪音特征带偏。
2. **不怕特征被"旋转"** —— 树是按单个特征切分的（"基因 A 表达 > 3 就分到左边"），
   不需要你先把特征变成某种坐标系。
3. **能学"不规则的函数"** —— 生物学里的关系大多是不规则的（剂量效应、阈值效应），
   树天生适合。

**对你的意义**：**你不需要把特征做得完美**。扔给树模型，让它自己挑。

### 2.3 三个库的差别（我们用这三个）

| 库 | 特点 | 什么时候用 |
|---|---|---|
| **LightGBM** | 最快，参数少，默认好用 | **默认主力** |
| **CatBoost** | **处理类别特征最好**（如"城市""机构编号"） | 类别列多的时候 |
| **XGBoost** | 最经典，文档最全 | 做对照 |

> ⚠️ **三个库的参数名不一样**！把 LightGBM 的参数直接抄给 XGBoost，它**不报错、
> 只是当没看见**，模型悄悄变差。这个坑我们踩过，已经做了拦截。

## §3 评估层（**最像生信的一层，也最重要**）

### 3.1 交叉验证（CV）

**你已经会了**：分成 K 折，轮流留一折做验证。

**这里的新问题**：这个比赛**每天只能提交 1 次**，而且**初赛不公布分数**。
所以你没有"榜单反馈"可以依靠——**本地交叉验证是你唯一的信息来源**。

⇒ 所以 CV 方案必须一开始就搭对。`make train` 会一次跑出"均值 ± 标准差"。

### 3.2 数据泄漏（leakage）—— **四种，都隐蔽**

你熟悉的是"数据被污染"。这里分成四类：

| 类型 | 长什么样 | 生信类比 |
|---|---|---|
| **预处理泄漏** | 先对**全部数据**做标准化/填补，再切分训练测试 | 用全队列算归一化因子，再用它分折 |
| **目标编码泄漏** | 用"类别对应的平均结果"造特征，但用了全部数据 | 用全部样本的生存信息造特征 |
| **时序泄漏** | 用未来的数据造过去的特征 | 用后测序的样本校正先测序的 |
| **ID / 顺序泄漏** | 行号或 ID 和结果相关（数据按结果排过序） | 样本编号和分期相关 |

⇒ 这条我做成了一道门（**G3**），并且写了 `make validate`。

### 3.3 对抗验证（adversarial validation）—— **就是"批次效应检测"**

**你已经会了，只是没这么叫过。**

做法：把训练集标 0、测试集标 1，混在一起训一个模型去猜"这行来自哪边"。

- **猜不出来（AUC ≈ 0.5）** → 两边同分布，**你的本地验证分数可以信**
- **一猜就中（AUC 明显高）** → 两边不同分布，**本地分数虚高，线上会崩**

**这就是你的批次效应检测，一模一样。** 而且它还能告诉你"是哪些字段在漂移"。

> ⚠️ 诚实说明：这**不是学术论文提出的**，是 Kaggle 社区发明的工程技巧，
> 学术上是后来引用它。论文里引用时别假装它源于某篇开创性论文。

### 3.4 消融实验（ablation）—— **和 knockout 完全一样**

**你已经会了**：想知道某个基因有没有用，就把它敲掉，看表型变不变。

做法：把你做的每一组特征**轮流砍掉**，看主指标掉多少。

- **掉了** → 这组有用，写进论文（"砍掉后从 0.89 掉到 0.87"）
- **没掉甚至变好** → 这组是噪音，**必须下线**

**这是论文里最实在的加分项。** 别人说"我们加了 X 特征效果更好"，
你说"我们砍掉 X，主指标从 A 掉到 B"——后者才叫论证。

## §4 集成层：为什么"多个模型"比"一个好模型"

### 4.1 核心直觉

**你已经在做这件事了**：判定一个细胞是不是 T 细胞，你不会只看 CD3D 一个基因，
而是看**一整套 marker**——因为每个 marker 犯错的方式不一样，合起来更稳。

**模型也一样**：LightGBM 和线性模型犯错的地方不一样，合起来比任何一个都稳。

### 4.2 三种"合起来"的方式（从简单到复杂）

| 方式 | 怎么做 | 特点 |
|---|---|---|
| **简单平均** | 几个模型的结果直接平均 | 最稳，但没利用"谁更可靠" |
| **堆叠（stacking）** | 训一个小模型，学"该信谁、信多少" | 更准，**但这就是"门控"容易混淆的地方** |
| **门控（gating）** | 让"信谁"**依赖这条样本长什么样** | 才能解释成"样本分群" |

> 🔴 **这两者的区别很重要**（我们专门讨论过）：
> - 只看**各模型的预测**决定怎么组合 → 学名叫 **stacking / 动态集成选择**
> - 看**样本特征**决定怎么组合 → 才叫 **门控 / 混合专家（MoE）**
>
> 区别在于**权重里有没有样本特征**。只有含特征，权重才能解释成"这条样本属于哪一类"。
> 论文里写错这个会被懂行的评审抓住。

### 4.3 ⚠️ 一句实话

**集成带来的提升通常只有 0–3%**（有实证）。别指望它翻天。
它的价值主要在**稳健性**和**论文叙事**，不在涨分。

## §5 前沿层：两件值得知道的事

### 5.1 共形预测 / 共形风险控制 —— **给结论加"保证"**

**你熟悉的类比**：置信区间。但共形预测更进一步——它**不依赖分布假设**，
而且**在小样本下仍然成立**（这点对生物学背景的人应该很有吸引力）。

**一句话**：不只是给一个预测值，而是给一个**预测集合**，并保证
"真值落进去的概率 ≥ 1−α"。

**共形风险控制**把它推广到"**任意损失的期望值**"——可以直接说
"**期望漏判率 ≤ 10%**"，而且这个保证是**可证伪的**，不是"我们觉得挺准"。

CPU 上五十行以内、秒级。已经实现好了（`src/conformal.py`）。

### 5.2 一个重要的"坏消息"——**知道哪些路是死的，比知道哪些是活的更有用**

学术界研究了十五年"怎么抗分布偏移"，最诚实的结论是：

> **专门的抗偏移算法（IRM / DRO / 域泛化）在真实任务上几乎打不过调好的普通模型。**

证据（我逐字核实过摘要原文）：
- **DomainBed**（ICLR 2021）：九个算法统一重跑，**"ERM 在所有数据集上都是 SOTA"**
- **《The Risks of IRM》**（ICLR 2021）：IRM "**可能灾难性失败**"，且"**根本上无法超越 ERM**"

**这对你们论文是个加分项**：写一句"我们查过这条路，有独立基准证明它打不过简单方法，
所以我们不做"——**比盲目堆一个上去强得多**，而且体现你懂前沿的边界在哪。

## §6 工程层（**你最陌生的部分，但评委很在意**）

这一层和生物学没关系，纯粹是"怎么让代码被别人拿去也能跑"。
**评分第二轴（代码完整性、正确性、效率）直接看这个。**

| 概念 | 是什么 | 为什么在意 |
|---|---|---|
| **git** | 代码的版本管理 | 评委可能要看你的修改历史 |
| **配置驱动** | 参数写在 `yaml` 文件里，不写在代码里 | 换实验不用改代码，也不会改错 |
| **固定随机种子** | `SEED=42`，保证每次跑结果一样 | **不复现的结果等于没有结果** |
| **一键复现** | `bash scripts/run_all.sh` 从头跑到尾 | 官方硬要求："代码完整、运行稳定" |
| **环境锁定** | `environment.yml` 记录所有包的版本 | 别人装一样的版本才跑得出来 |

**你不需要会写，但需要知道"为什么这件事重要"**：
评委会**拿着你的代码和数据去跑**，跑不通就直接丢分。

> **注意区分**：这和我平时说的"项目级门控"（`docs/门控系统.md`）是一件事的两面——
> 门控是**流程**（什么时候停下来检查），工程是**手段**（怎么让检查有依据）。

## §7 竞赛文化：**和发论文很不一样**

| | 发论文 | 这个比赛 |
|---|---|---|
| 时间 | 几个月到几年 | **7 天** |
| 最重要的产出 | 结果的可信度 | 结果 + **论文 + 代码**（三件套） |
| 反馈 | 审稿意见（几周后） | **每天只能提交 1 次，且初赛不公布分数** |
| 创新要求 | 新发现 | **新意可以来自"应用"，不一定要"发明"** |
| 失败的处理 | 可以只报阳性结果 | **要主动写缺点**（"模型评价"一节必看） |

**最关键的一条**：**这不是纯排行榜赛。** 评分四轴里，
论文质量和创新性占了一半，**光有高分模型不够**。

⇒ 所以你们花在**讲清楚"为什么这么做"**上的时间，和花在**调模型**上的时间一样值钱。

## §8 如果只记三件事

1. **你已经在做 80% 的事了。** 批次效应=分布偏移、留一法=交叉验证、knockout=消融、
   多 marker 判定=集成。**不要因为名字陌生就觉得是全新的东西。**
2. **这个比赛的瓶颈不是模型，是"可信度"和"讲清楚"。** 每天 1 次提交、
   初赛不公布分数——**你只能靠自己的严谨**。
3. **"知道哪些路走不通"和"知道哪些走得通"一样值钱。** 我们查过 IRM/域泛化那条线，
   有独立基准证明它打不过简单方法——**写进论文是加分，不是示弱**。
