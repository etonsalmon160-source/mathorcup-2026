# 复现规范

评分轴② = **代码完整性、正确性和效率**；轴①也要求"实验程序正确"。
评审是**拿着你的代码和数据去跑**的，跑不通 = 直接丢分。这份规范就是为了让代码跑得通。

---

## 0. 代码模块一览（骨架已就绪）

| 模块 | 干什么 |
|---|---|
| `src/config.py` | 路径、种子、线程数、日志、实验台账的**唯一入口** |
| `src/data.py` | 读数据 + 数据体检（`make data`），开赛第一步 |
| `src/features.py` | 通用特征（日期拆解/行统计/缺失模式/频次编码）+ **`domain_features()` 领域特征入口** |
| `src/cv.py` | 交叉验证切折（分层/K折/时序）+ 指标 + 基线对比 |
| `src/models.py` | LightGBM / XGBoost / CatBoost 统一封装 |
| `src/train.py` | 训练主入口：CV → 报均值±标准差 → 全量重训 → 存产物 → 记台账 |
| `src/predict.py` | 出提交文件（分类额外给概率列） |
| `src/plots.py` | 出图到 `figures/<实验名>/`，直接进论文 |
| `src/selftest.py` | **改完代码先跑 `make smoke`**，用造假数据验证整条流水线没坏 |

> **改代码后必跑 `make smoke`**（约 1 分钟）。它跑完 6 组组合
> （分类/回归 × 三个模型）外加检查 `src/configs/` 下每份配置能不能训起来。
> 这是"代码是对的"的唯一证据——比赛期间别靠肉眼读代码。

## 1. 一入口原则

**任何人拿到仓库，只跑一条命令就能复现全部结果。**

```
bash scripts/run_all.sh [配置路径]     # 从 raw 数据到最终提交文件
```

- 中间步骤可以分开，但 `run_all.sh` 必须把它们串起来、按序执行。
- 每个脚本都要能**单独重跑**（幂等：跑第二遍结果一样，不报错）。

## 2. 路径只在一个地方定义

所有路径来自 `src/config.py` 的 `PATHS`，**不许在脚本里写死绝对路径**。
别人 clone 到你机器以外的地方也能跑。

## 3. 随机种子与线程数

- 全局种子在 `src/config.py` 的 `SEED`（默认 42）。
- 每个涉及随机的步骤显式传种子：`train_test_split(..., random_state=SEED)`、
  `lgb.train(..., seed=SEED)`、`np.random.default_rng(SEED)`。
- 对**结果敏感的模型**（如 LightGBM、XGBoost），跑 **3 个种子取平均**并报标准差——
  论文里报"均值 ± 标准差"比报单个数可信得多，也顺带证明结果稳。

```python
from src.config import SEED, set_global_seed
set_global_seed(SEED)
```

**线程数不要写 `-1`。** 本机 20 核实测：LightGBM 开 `n_jobs=-1` 会让一次 0.1 秒的训练
退化成几分钟卡死（线程互相抢占空转）；4 线程反而最快，16 线程比 4 线程慢 2.7 倍。
默认上限在 `src/config.py` 的 `N_JOBS`（8），要调就在配置里写 `params.n_jobs`。

## 4. 实验配置化

实验参数写在 `src/configs/*.yaml`，不在代码里改。

```yaml
# src/configs/baseline.yaml
model: lightgbm
params:
  n_estimators: 800
  learning_rate: 0.05
seed: 42
cv_folds: 5
```

跑实验：`python -m src.train --config src/configs/baseline.yaml`
**每次跑的配置、指标、时间戳自动写进 `results/`**，形成实验台账。

## 5. 日志

- 每个脚本开头打一行：时间、脚本名、配置哈希、数据版本。
- 重要中间结果落盘（parquet/csv），别只存在内存里。
- 长跑（>30 分钟）必须**可断点续跑**（中间产物存在就跳过）。

## 6. 环境锁定

- 环境定义在 `environment.yml`；实际版本快照在 `docs/环境版本快照.txt`（`pip freeze` 生成）。
- **提交前**确认 `environment.yml` 能从零装出同样的环境。
- 交给评审的支撑材料里**必须**含 `environment.yml` + 一份 `README_运行说明.md`。

## 7. 提交前的复现自检清单

- [ ] 在**干净的目录**里 clone/copy 一份仓库
- [ ] `bash scripts/run_all.sh` 从零跑到底，不报错
- [ ] 输出的提交文件与最终提交的**逐字节一致**（或指标一致）
- [ ] `README_运行说明.md` 里的命令确实能跑（没用过时的写法）
- [ ] 没有硬编码的绝对路径、没有本地才有的文件依赖
- [ ] 所有数据文件都在支撑材料里（或明确说明获取方式）

## 8. 提交规范（官方）

- 提交**电子版论文 + 结果数据集 + 计算程序源代码**。
- 源程序即使已放进论文附录，**仍要单独以支撑材料提交一份**。
- 支撑材料压缩打包（zip/tar.gz），**单文件别超平台限制**，数据太大就说明获取方式。
- **每天只能提交 1 次** → 提交前走完上面第 7 节清单。
