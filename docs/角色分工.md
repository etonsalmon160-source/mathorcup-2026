# 三人分工与协作约定

评分四轴里，**③测试集指标**是 CS 哥的主场，**①论文质量**和**②代码质量**是全员的事，
**④创新性 + 跨学科交叉**靠三人合起来打。下面按"谁对什么负责、产出什么、什么时候交接"来分。

---

## 角色

### A — 系统生物学 / 组学（你）

**负责：把数据"读懂"，把结论"讲圆"。**

- 领域理解：拿到赛题背景后，先把业务/科学问题翻译成可建模的形式。
- 特征工程：领域驱动的特征设计（这是你相对 CS 哥的差异化优势——
  通用特征工程谁都会，**领域特征**才是创新点）。
- 结果解读：模型给出的重要特征/分群，要能说出它**在现实里意味着什么**。
- 论文主线：摘要、引言、问题分析、结论与展望。

**交接物**：`docs/问题理解.md`（开赛 6 小时内出）、特征字典、结果解读段落。

### B — CS

**负责：把想法"跑出来"，把代码"交得出手"。**

- 数据管线：读入、清洗、切分、缓存（大表走 parquet）。
- 建模与调参：baseline → 主模型 → 融合；`optuna` 调参。
- 代码工程化：`src/` 可复用、`scripts/` 可一键复现、有 `requirements`/`environment.yml`。
- **复现保障**：固定种子、配置驱动、日志齐全——这是评分轴②的命脉。

**交接物**：`src/` 下可运行代码、`results/` 指标表、`scripts/run_all.sh`。

### C — 经济学

**负责：把方案"卖出价"，把指标"设计对"。**

- 问题建模：从业务/经济视角定义目标函数、约束与权衡
  （例如"提升 1% 召回能让企业省多少钱"这种论证，评审很吃）。
- **评价指标设计**：赛题给的指标之外，主动补一套业务指标；
  这一条直接对上评分轴④的"跨学科交叉应用能力"。
- 敏感性 / 成本收益分析：模型阈值怎么定、误判代价不对称时怎么办。
- 论文的创新性论证：把"我们为什么这么设计"写成有说服力的论证。

**交接物**：`docs/指标体系.md`、论文的创新点章节、答辩 PPT 的经济论证部分。

---

## 协作约定（三条，别多）

1. **一个仓库，一条主干。** 谁改 `src/` 谁负责让它跑得通。
   改动前 `git pull`，改完当天推。冲突当面解，不用 `--force`。
2. **数据与结论分离。** 原始数据只进 `data/raw/`（只读）；任何处理都是脚本（`src/`），
   不是手工在 Excel 里改。手工改动不可复现，评分轴②会扣分。
3. **每天 22:00 站会 15 分钟。** 三问：今天出了什么数、卡在哪、明天谁交什么。
   要提交的话，**先写 `submissions/REGISTRY.md` 再上传**。

## 时间分配建议（初赛 7 天）

| 时段 | A（你） | B（CS） | C（经济） |
|---|---|---|---|
| D1 前 6h | 读懂赛题、写问题理解 | 数据加载与体检 | 定义业务目标与指标 |
| D1–D2 | 领域特征设计 | baseline 跑通 | 指标体系文档 |
| D3–D5 | 特征迭代 + 结果解读 | 模型迭代 + 调参 | 敏感性/成本分析 |
| D6 | 论文主线撰写 | 代码整理 + 复现验证 | 创新点论证 + 图表 |
| D7 | 论文统稿、定稿 | 打包支撑材料 | 答辩预案（备用） |

> 复赛若晋级：**换数据但背景不变**，D1–D2 可以复用大半，主要精力放在模型的泛化与稳健性上。
