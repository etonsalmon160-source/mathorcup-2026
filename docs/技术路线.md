# 技术路线（含具体参数）

> 依据三份赛前文献调研（表格 SOTA / 状态空间 / 门控与集成）写成，引文见 [文献库.md](文献库.md)。
> **本文件管"用什么、参数填多少"**，[门控系统.md](门控系统.md) 管"什么时候必须停下来"。

---

## 0. 三条核心判断（先看这个，它决定了后面所有设计）

1. **涨分的主力是特征与验证，不是换更炫的模型。**
   TabArena (2025) 明确指出：**没有任何单一模型通吃，跨模型集成才是新的 SOTA**；
   而 Grinsztajn (2022) 的"树模型仍胜深度学习"在中等规模数据上至今成立。
   ⇒ 我们把力气花在**领域特征 + 稳健验证 + 融合**上。

2. **表格基础模型（TabPFN 系）是真正的变量，但只在小样本上。**
   TabPFN v2 上了 **Nature 正刊**，在 ≤1 万行数据上不调参就能超过调参后的 GBDT。
   但它有硬上限（v2: 1 万行/500 列；2.5: 10 万行）。
   ⇒ **数据规模决定要不要请它出场**，见 §3。

3. **状态空间模型的价值在"当特征"，不在"当主模型"。**
   在 CPU 上从零训 Mamba 性价比极低；但用 `statsmodels` 把**潜状态（水平/斜率/季节）分解出来喂给 GBDT**，
   成本近乎为零，且有实证先例（Soybilgen & Yazgan 2021：动态因子 + 树集成 nowcast 美国 GDP）。
   ⇒ 这是我们**性价比最高的创新点**，也是经济哥的主场。

> 一句话总结打法：**GBDT 打底，状态空间加特征，门控做融合，经济学定阈值。**

## 1. 三层架构

```
┌─ 特征层 ────────────────────────────────────────────┐
│  通用特征（已有）  +  领域特征（生信）  +  潜状态特征（经济）│
│  日期拆解 / 行统计 / 缺失模式 / 频次                    │
│  + domain_features()                ← 你的主场        │
│  + Kalman 潜状态 / 结构分解 / 动态因子 ← 高性价比创新点  │
└──────────────────────┬───────────────────────────────┘
                       ↓
┌─ 专家层（异构，4 个）────────────────────────────────┐
│  LightGBM  ·  CatBoost  ·  线性模型  ·  [TabPFN v2]   │
│  各自跑同一套折 → 产生样本外（OOF）预测                 │
└──────────────────────┬───────────────────────────────┘
                       ↓
┌─ 决策层 ────────────────────────────────────────────┐
│  软门控（OOF → 元学习器）→ 融合预测                     │
│  + 成本敏感阈值（经济学）→ 最终判定的取舍               │
└─────────────────────────────────────────────────────┘
```

**为什么专家必须异构**：同质专家堆一起没有意义。线性模型虽然弱，
但它**犯错的方式和树模型不一样** —— 这正是融合能赚到钱的地方。
实测（合成数据）已经看到：最容易的样本上 LightGBM 最强，最难的样本上线性模型反超。

## 2. 具体参数

### 2.0 用"抄来的"默认值，不要自己拍

下面三组参数**不是我们拍脑袋定的**，抄自：

> **Holzmüller, Grinsztajn, Steinwart. *Better by Default: Strong Pre-Tuned MLPs and
> Boosted Trees on Tabular Data*. NeurIPS 2024. arXiv:2407.04491**（`holzmuller2024better`）

这篇论文专门研究"预调好的默认超参"：在 **118 个数据集**上调出来、在 **90 个不相交数据集**上验证。
论文结论一句话：

> **"Best-TD（这套默认值）平均比 50 步 HPO 更快，同时与最好的 HPO 模型有竞争力。"**

也就是说，**抄这套默认值 ≈ 省掉 50 步调参**，而且不用赌运气。
数字已与论文附录 Table C.1–C.3 及官方开源仓库 `pytabkit/models/sklearn/default_params.py`
**逐字核对一致**，并已写进 `src/configs/*.yaml`。

论文给出的三条规律（帮你们理解为什么这么设）：
- **行采样几乎总有用，列采样很少有用**（所以 `subsample < 1`、`colsample = 1.0`）
- **回归的树该更深**（XGB/CatBoost 回归 `depth=9`，分类只要 6/7）
- CatBoost 的 Bernoulli bootstrap 与 Bayesian 效果相当但更快

### 2.1 LightGBM（主力）

| 超参 | 分类 | 回归 |
|---|---|---|
| `n_estimators` | 1000 | 1000 |
| `learning_rate` | 0.04 | 0.05 |
| `num_leaves` | 50 | 100 |
| `min_child_samples` | 40 | 3 |
| `min_sum_hessian_in_leaf` | 1e-7 | 1e-7 |
| `subsample` | 0.75 | 0.7 |
| `bagging_freq` | 1 | 1 |
| `colsample_bytree` | 1.0 | 1.0 |
| `max_bin` | 255 | 255 |

> ⚠️ `n_estimators=1000` 是**配早停用的**，真正用的是最优迭代数，不是硬跑 1000 棵。
> 早停要用**折内再切出来的一小块**验证集，不能拿 CV 的验证折去早停（那会让分数虚高）。

### 2.2 XGBoost

| 超参 | 分类 | 回归 |
|---|---|---|
| `n_estimators` | 1000 | 1000 |
| `learning_rate` | 0.08 | 0.05 |
| `max_depth` | 6 | 9 |
| `min_child_weight` | 5e-6 | 2.0 |
| `subsample` | 0.65 | 0.7 |
| `colsample_bytree` / `colsample_bylevel` | 1.0 / 0.9 | 1.0 / 1.0 |
| `reg_lambda` | 0.0 | 0.0 |
| `max_bin` / `tree_method` | 256 / hist | 256 / hist |

### 2.3 CatBoost（类别特征多时改用它当主力）

| 超参 | 分类 | 回归 |
|---|---|---|
| `iterations` | 1000 | 1000 |
| `learning_rate` | 0.08 | 0.09 |
| `depth` | 7 | 9 |
| `l2_leaf_reg` | 1e-5 | 1e-5 |
| `bootstrap_type` / `subsample` | Bernoulli / 0.9 | Bernoulli / 0.9 |
| `random_strength` | 0.8 | 0.0 |
| `one_hot_max_size` | 15 | 20 |
| `leaf_estimation_iterations` | 1 | 20 |
| `max_bin` | 254 | 254 |

> CatBoost 的 ordered target statistics 是高基数类别的理论级解法（Prokhorenkova 2018）。

### 2.4 线性专家（融合用的多样性来源）

`LogisticRegression(max_iter=2000)` / `Ridge()`，配 `SimpleImputer(median)` +
`OneHotEncoder(min_frequency=5)`。由 `src/fuse.py` 自动组装，无需配置。

> 别小看它。实测（合成数据）里，**最容易的样本上 LightGBM 最强，最难的样本上线性模型反超**——
> 这正是融合能赚到钱的地方。

### 2.5 要不要调参：先不调，要调就照这个来

**第一步（几乎不花时间）**：直接用 §2.1–2.3 的默认值，三个模型各跑一遍 CV，选最好的那个。
论文背书：这一步通常已到 50 步 HPO 的水平。

**第二步（有余力再上）**：Optuna（默认就是 TPE），**trials 设 50–100**。

| 数据规模 | trials | 墙钟时间盒 |
|---|---|---|
| < 10 万行 | 80 | **60 分钟** |
| 10–100 万行 | 40 | 90 分钟 |
| > 100 万行 | 20 | 60 分钟（**用子采样调参**） |

**优先搜什么**（有实证依据 —— Probst et al. JMLR 2019 的参数重要度排序）：
1. **`learning_rate`（最重要）** 和 booster 类型
2. 树的复杂度（`num_leaves` / `max_depth`）
3. `min_child_samples` / `min_child_weight`、`subsample`
4. 正则项 `l1`/`l2` 放**最后**

```python
{
  "learning_rate":     trial.suggest_float("learning_rate", 0.005, 0.1, log=True),
  "num_leaves":        trial.suggest_int("num_leaves", 15, 127, log=True),
  "min_child_samples": trial.suggest_int("min_child_samples", 5, 100),
  "subsample":         trial.suggest_float("subsample", 0.5, 1.0),
  "colsample_bytree":  trial.suggest_float("colsample_bytree", 0.5, 1.0),
}
```

**别做的事**：别调随机森林（Probst 实测几乎不可调）；
别用 Hyperband 或大网格（实证更差）；别指望 stacking 带来大提升（实测通常只有 **0–3%**）。

### 2.5 状态空间特征（**性价比最高的一块**）

用 `statsmodels`，**纯 CPU、秒级**：

```python
from statsmodels.tsa.statespace.structural import UnobservedComponents

# 按实体（门店/用户/设备）逐条拟合，抽出潜状态当特征
mod = UnobservedComponents(y, level="local linear trend", seasonal=7,  # 周周期
                           stochastic_seasonal=True)
res = mod.fit(disp=False)
features = {
    "潜状态__水平": res.level.smoothed[-1],
    "潜状态__斜率": res.trend.smoothed[-1],
    "潜状态__季节": res.seasonal.smoothed[-1],
    "潜状态__水平波动": res.level.smoothed.std(),
}
```

- **`seasonal` 填什么**：日数据填 7，月数据填 12，周数据填 52。
- **不适用时**：若赛题无时序结构（纯横截面表格），这一块整个跳过，别硬凑。
- **代价估计**：单条序列拟合 < 0.1 秒；1 万条实体约 10–15 分钟。**实体数 > 5 万就采样一条子集抽特征规律，别全量做。**

> 这是经济哥的主场，也是跨学科叙事的技术支点：
> 卡尔曼滤波（Harvey 1989; Durbin & Koopman 2012）在工程/经济叫"状态空间"，
> 在生物学叫"隐状态动力学"—— 数学上是同一个东西（Auger-Méthé 2021）。

### 2.6 融合与门控（**术语必须说准，否则是硬伤**）

这里有一个**很容易被懂行评审抓住的坑**，先说清楚：

| 门控看什么 | 学名叫什么 |
|---|---|
| 只看各专家的**预测** | **stacking / 动态集成选择（DES）** —— Wolpert 1992；`cruz2018dynamic` |
| 看**输入特征 x** | 才叫 **mixture of experts（门控）** —— `jacobs1991adaptive` |

**权重里有没有样本特征，决定了它是不是"门控"。**
如果门控只看专家的预测，那逐样本权重没有"亚群"含义——因为权重里根本没包含样本长什么样，
论文里"门控权重 = 样本亚群"这句话就立不住。

所以我们实现的是**后者**（`src/fuse.py` 的 `softmax_gate`）：

```
w_k(x) = softmax_k( A_k · φ(x) + b_k )      每条样本一套权重，和为 1
ŷ(x)   = Σ_k w_k(x) · z_k(x)                按权重把专家加起来
```

`src/fuse.py` **四种方案同台对比**，用同一套折：

| 方案 | 说明 |
|---|---|
| 最好单模型 | 参照基线 |
| 简单平均 | 等权 |
| **线性堆叠** | 只学 K 个系数，只看预测（= DES） |
| **软门控** | 学 K×(d+1) 个参数，看特征（= MoE） |

> ⚠️ **实测提醒**：软门控参数多得多，**小数据上打不过线性堆叠是正常的**
> （我们在合成数据上就复现了这一点）。论文里要**如实写**，别硬说门控更好。
> 门控的价值在于**可解释性**（权重 = 亚群），不在涨点。

- 门控器的输入用 **OOF 预测 + 样本特征**，逐折拟合、逐折评估，不泄漏。
- **G5 护栏**：三种组合方式里最好的那个，赢不过最好单模型就**退回单模型**。
  2025 基准支持"没有单一模型通吃"，但也不支持硬融。

### 2.7 成本敏感阈值（经济学，直接对标第 4 轴）

默认 0.5 阈值只对"误判代价对称"成立。真实业务里几乎从不对称。

```
期望损失(阈值 t) = C_FP · FP(t) + C_FN · FN(t)
最优阈值 t* = argmin_t 期望损失(t)
```

实现：`make predict CONFIG=... ` 时加 `--threshold`；
把 FP/FN 的历史 COP 数据画成曲线（`src/plots.py` 已有概率分布图，再加一张"阈值 vs 期望损失"图）。

> 论文里写"提升召回 1% 相当于给企业省 X 万元"这类论证，评审很吃。

## 3. 按数据规模决定要不要请 TabPFN

D1 拿到数据先数样本量 N，然后照这张表走：

| 规模 | 主力 | 要不要 TabPFN | 理由 |
|---|---|---|---|
| **N ≤ 1 万** | GBDT + **TabPFN v2** | **要**，优先试 | Nature 正刊结论：小样本上不调参即超越调参 GBDT；CPU 推理几十秒 |
| **1 万 < N ≤ 10 万** | GBDT 为主 | 试 TabPFN-2.5 / TabICLv2，**先实测单折耗时** | 单折 > 20 分钟就放弃，别赌 |
| **N > 10 万** | GBDT + 集成 | **不要** | 超出 TFM 甜区，收益收窄 |

> **必须先实测再决定**。装 TabPFN 前先跑一个 5 分钟的最小例子，
> 确认能装上、能推理、耗时可接受 —— 这是 G2 之前就该做的 5 分钟投资。

## 4. 明确不做的事（省时间）

| 不做 | 为什么 |
|---|---|
| **从零训 Mamba / S-Mamba 当主模型** | 官方实现依赖 CUDA 内核，CPU 上要么没加速要么用纯 PyTorch 版慢得多；7 天内调不完参，且"no champions"(2025) 证明这类 SOTA 排名高度依赖调参口径 |
| **FT-Transformer / SAINT / TabNet** | 现代基准里已被 MLP 系反超（TabM 2025），CPU 又慢 |
| **稀疏 top-k MoE + 负载均衡损失** | 那是 GPU 集群扩容的手段，小数据上约等于随机路由 |
| **把 target encoding 当默认** | 2023 年 OpenML 全量实证：多分类任务里 one-hot 反而更好 |
| **上来就做深度缺失值插补** | GBDT 原生缺失处理通常就够，先把它当对照 |

## 6. 创新点怎么写 —— **先说难听的**

我们对这几块做过一次**独立的新颖性审查**（专门去查"有没有人做过一模一样的事"）。
**结论很不客气，必须让你们知道：**

> **这五块里没有一块是新的。**
> 潜状态当特征有**几乎逐字对应**的论文（`pellegrino2021factor`，标题就叫 *Factor-augmented tree ensembles*，
> 摘要原话是"用状态空间方法提取潜平稳因子加进时序回归树"）；
> 门控权重当亚群有 **1995 年**的标题（Weigend et al. 的 "Discovering regimes"）和医疗场景的逐字版本
> （`huo2021sparse`）；成本敏感阈值是 2001 年的教科书内容（Elkan）。

### 所以正确的写法是：**不要宣称框架创新**

评审如果判"这是 stacking + 卡尔曼特征 + MoE 可解释性 + 阈值优化，四样现成东西拼起来"——
**这个判决在组件层面无法反驳。** 硬吹反而更容易翻车。

**改成这样立**：不宣称"我们提出了新方法"，而宣称

> **我们对这些问题做了预注册、可复现、带消融与成本论证的严格应用，并给出了一个针对本赛题的具体发现。**

这满足的是评分第 4 轴的**"跨学科交叉应用能力"**（这一半比"创新"宽容得多）+ 第 2 轴（代码质量）。
**新意应该落在"发现"上，不落在"框架"上。**

### 那"发现"从哪来？—— 三块，各对一个人

| 可能的发现 | 技术载体 | 谁主责 | 引文支点 |
|---|---|---|---|
| **领域机制特征带来的具体增益** | `domain_features()` | A 生信 | Grinsztajn 2022（特征比模型重要） |
| **不可观测驱动因子的拆解** | Kalman / 结构分解当特征 | C 经济 + A | `soybilgen2021nowcasting`; `pellegrino2021factor`; Auger-Méthé 2021; Cai 2024 |
| **样本异质性 → 亚群 → 差异化决策** | 软门控权重当作分群 | C 经济 | `huo2021sparse`; Weigend 1995; Wager & Athey 2018; Künzel 2019 |

第三块最"跨学科"：**同一个门控权重，生物侧讲亚型、经济侧讲异质性处理效应、
CS 侧讲集成与消融** —— 三个学科各讲一遍。

> ⚠️ 但记住：文献里软门控在表格数据上的增益是**"持平到小幅领先"**（`chernov2025ggmoe`，38 个数据集实测），
> **不是碾压**。定位成"可解释性与稳健性的载体"，不要写成"涨点银弹"。

### 创新点的自检句（写完拿这句话照一遍）

社区总结的**伪创新检验句**，填不满就是伪创新：

> **"当参数/结构/机制从 A 变到 B 时，可观测指标从 X 变到 Y，因为〔机制解释〕；
> 在 Z 条件下这个优势消失。"**

对照检查你们的每一条创新：
- ❌ "我们使用了 LightGBM + 门控" → 填不满，这是**堆模型名称**，评委最反感
- ❌ "我们首次将 X 应用于 Y" → 无法证实，别写"首次/领先"
- ✅ "**砍掉潜状态特征组后，主指标从 0.89 掉到 0.87（−0.02，超过种子间标准差），
  因为该特征组承载了____的时序结构；但当序列长度短于一个完整季节周期时，这个优势消失**"
  → 这条填满了：有 A→B、有具体数字、有机制、有边界条件

### 必须引齐的"最接近的已有工作"

不引这几条，懂行的评审会认为你们**没做功课**（这比创新不足更伤）：

`pellegrino2021factor`（潜状态当特征）· `cruz2018dynamic`（动态集成选择综述）·
Weigend 1995（门控发现 regime）· `huo2021sparse`（门控=亚群，医疗）·
`elkan2001foundations`（成本敏感学习）· `chernov2025ggmoe`（表格上的软门控到底值不值）

> 主动引齐 + 明确写"我们不是提出新算法，而是把 X/Y/Z 组合应用于本业务问题并做严格消融"——
> 评审吃"我知道我是什么、我也知道我**不是**什么"，远胜含糊吹创新。
