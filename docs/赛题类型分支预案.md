> **为什么要有这份文件**：现有的全套准备（特征工程、三模型、融合门控、状态空间特征）
> **都建立在"结构化表格数据"这个假设上**。但赛题也可能是文本或时序。
> 万一 10-23 开出来不是表格题，你们不能当天从零现想——D1 还要读题、体检、出 baseline。

> **这份文件的用途**：D1 前 30 分钟判类型 → 直接跳到对应章节 → 照抄起手式。

## −1. 🔴 先看任务类型，再看数据模态（**比模态更重要**）

上面 §1–§5 说的都是**数据长什么样**（表格 / 文本 / 时序 / 图像）。
但还有一个**更要命**的维度：**赛题让你干什么？**

数学建模竞赛的题型大致分六类，**我们现在只准备了第一类**：

| 题型 | 赛题通常怎么问 | 我们的准备 | 主力方法 |
|:---:|---|:---:|---|
| **预测类** | "预测下个月的销量 / 判断该客户会不会流失" | ✅ **充分** | 梯度提升树 + 决策层（已就绪） |
| **分类 / 聚类** | "把客户分成几类 / 识别异常样本" | 🟡 **部分**（特征与树模型能复用，但**评价指标完全不同**：要轮廓系数、ARI、业务可解释性） | KMeans / 层次聚类 / UMAP + 业务标签 |
| **评价类** | "构建 xx 的评价指标体系 / 给这些城市排名" | ❌ **空白** | AHP / 熵权法 / TOPSIS / 主成分 —— **这是数模的经典套路** |
| **优化类** | "给出最优调度方案 / 成本最小的配置" | ❌ **空白** | 线性/整数规划、启发式、`scipy.optimize`（环境里有，没准备用法） |
| **统计 / 机理** | "分析 xx 与 yy 的关系 / 建立机理模型" | ❌ **空白** | 回归诊断、假设检验、`statsmodels`、微分方程 |
| **方案设计** | "给企业提一套方案 / 设计一套流程" | ❌ **空白** | 需要**论证与包装**，模型只是配角 |

> 🔴 **这是整个赛前准备里最大的单点风险。**
> 我们花了大量精力在"预测 + 决策"这一条线上（梯度提升树、消融、对抗验证、共形风险控制），
> **但如果 10-23 开出来的是"评价类"或"优化类"，这一整套几乎用不上。**
>
> 更麻烦的是：**数模竞赛里"评价类"和"优化类"恰恰是最高频的题型。**
> 预测类反而更常见于 Kaggle 那种纯数据竞赛。

### 怎么补（开赛前剩下的时间）

**不必重做全套，只需各备一个"能跑的起手式"：**

| 题型 | 开赛前的准备（各约 1 小时） |
|---|---|
| 评价类 | 实现 AHP + 熵权法 + TOPSIS 三个函数（`src/evaluate.py`），输入一个决策矩阵就能出结果。**这是数模最经典的组合，几乎每年都有人用** |
| 优化类 | 摸清 `scipy.optimize.linprog` / `milp` 的用法；备一个整数规划小例子。环境里 `scipy` 已装 |
| 统计 / 机理 | `statsmodels` 的回归诊断、假设检验已经会（[技术路线.md](技术路线.md) §2.5 用过） |
| 分类 / 聚类 | 特征和树模型可复用；**但要把评价指标换掉**（轮廓系数 / ARI / 业务解释），不能只看准确率 |

> **判断方法（D1 前 10 分钟）**：读题，找动词。
> "**预测**" → 预测类；"**评价 / 排名 / 构建指标**" → 评价类；
> "**最优 / 最小成本 / 安排**" → 优化类；"**分析关系 / 机理**" → 统计类；
> "**给出方案**" → 方案设计。
>
> **一道题常常是复合的**（例如"先评价再优化"），那就按**主问题**定主线。

## 0. D1 判类型（10 分钟内做完）

开赛后拿到数据，**先看文件清单**，对号入座：

| 你看到什么 | 判定 | 去哪一节 |
|---|---|---|
| `.csv` / `.xlsx` / `.parquet`，一张或多张**宽表**，一列是要预测的目标 | **结构化表格** | §1 |
| 表里有一列是**长文本**（评论、申报材料、日志、工单），或干脆是一堆 `.txt` | **文本为主** | §2 |
| 有明确的**时间列**，且同一实体有多个时间点（销量/流量/股价/监测值） | **时序** | §3 |
| 一堆 `.jpg` / `.png` / `.dcm`，或要求分类/检测图像 | **图像** | §4 ⚠️ |
| 混合：表格 + 文本 + 时间 | **多模态拼接** | 按**主表**定类型，其余当特征 |

> **关键判断（30 秒版）**：打开主表，问一句——
> **"每一行代表什么？"**
> - 一行一个**实体**（用户/门店/订单）→ 表格
> - 一行一个**时间点** → 时序
> - 一行一段**文字** → 文本

## 2. 文本为主

**环境里有**：`jieba`（中文分词）、`sklearn`（TF-IDF）、`wordcloud`。
**环境里没有**：`torch`、`transformers`（所以**不能用 BERT 微调**）。

### 2.1 起手式：TF-IDF + 梯度提升树

**中文文本不用分词也能跑** —— 字符 n-gram 对中文效果往往比分词更好，且省掉分词这一步的坑。

```python
from sklearn.feature_extraction.text import TfidfVectorizer

# 关键参数：字符 n-gram（中文的关键）
vec = TfidfVectorizer(
    analyzer="char_wb",      # 按字符，中文友好
    ngram_range=(2, 4),      # 2~4 字的片段
    min_df=3,                # 丢掉只出现 1~2 次的
    max_features=200_000,    # 封顶，防内存炸
    sublinear_tf=True,       # 长文本抑制，文本分类常用
)
```

流程：
1. **TF-IDF 字符 n-gram** → 稀疏矩阵
2. 线性模型打底（`LogisticRegression` / `SGDClassifier`）—— **先跑通再说**
3. **接 LightGBM**（`scipy.sparse` 直接喂得进）—— 通常比线性好一点
4. 文本长度 / 标点密度 / 是否含数字 等**元特征**和 TF-IDF 拼起来

### 2.2 文本特有的坑

| 坑 | 说明 |
|---|---|
| **必须只在训练集 fit 向量化器** | 否则测试集词汇泄漏进训练（典型预处理泄漏，见 [门控系统.md](门控系统.md) D1） |
| 类别不平衡 | 评论类数据常极度不平衡，**别只看准确率** |
| 长文本 | 太长先截断，TF-IDF 对超长文本不友好 |
| 中文编码 | 先确认是 UTF-8 还是 GBK，读进来乱码后面全废 |

### 2.3 时间估算

TF-IDF + 线性模型在 10 万条文本上 **几分钟**；接 LGBM 再加十几分钟。**D1 当天能出 baseline。**

> **可选增强（若有云 GPU）**：中文预训练模型抽句向量再接树模型。但**先确认 GPU 可用性**，
> 别把宝押在上面。

## 3. 时序

**环境里有**：`statsmodels`（卡尔曼滤波 / SARIMAX / 结构分解）、`sklearn`（TimeSeriesSplit）。

### 3.1 🔴 第一件事：切分必须按时间

**这是时序题最常见的翻车点。** 随机 K 折会让模型"偷看未来"，本地分数虚高，线上崩盘。

```yaml
cv:
  strategy: timeseries
  sort_by: 日期列名        # ← 必填，否则代码会按原顺序切，等于作弊
  n_splits: 5
```

`src/cv.py` 已支持，`make train` 会自动按 `sort_by` 排序再切。

### 3.2 特征重点：把"时间结构"显式造出来

树模型学不会"2019-01-31 到 2019-02-01 只差一天"，必须手工告诉它。

| 特征类 | 具体做法 |
|---|---|
| **滞后特征（lag）** | `y[t-1], y[t-2], …`；`x[t-1], x[t-7], …` |
| **滚动统计** | 过去 7/14/30 天的均值、标准差、最大最小、趋势 |
| **周期编码** | 星期、月、季度、是否节假日、**距月末天数** |
| **潜状态特征** | `statsmodels` 的 `UnobservedComponents` 拆出水平/斜率/季节（见 [技术路线.md](技术路线.md) §2.5） |
| **交叉特征** | 实体 × 时间（如"该门店上周的均值"） |

> **`src/features.py` 的 `add_datetime_features` 已经能做日期拆解**，
> 滞后与滚动特征需要按赛题补（可以让我加）。

### 3.3 时序特有的坑

| 坑 | 说明 |
|---|---|
| **未来信息泄漏** | 最致命。用了 `t` 时刻之后的数据造 `t` 的特征 |
| **滚动统计忘了 shift** | 算"过去 7 天均值"时把当前天也算进去了 = 泄漏 |
| **预测跨度（horizon）** | 是预测下 1 期还是下 N 期？决定特征怎么造 |
| **分布漂移** | 时序数据训练/测试天然不同分布 → **对抗验证 AUC 必然偏高**（见 [门控系统.md](门控系统.md) G3），要按时序口径解读，别机械套 0.6 阈值 |

### 3.4 时间估算

特征工程占大头。**D1–D2 出 baseline，D3–D4 迭代特征。**

## 4. 图像 ⚠️ —— **这是最薄弱的一环**

**环境里没有 `torch`、没有 `transformers`，也没有 GPU。** 意味着**不能微调预训练模型**。

### 4.1 现实判断

| 情形 | 方案 |
|---|---|
| **能拿到 GPU** | 预训练 backbone 抽特征 → 树模型；或直接微调。**开赛前必须先验证那台机器真的能用** |
| **只有本机 CPU** | 只能用 `opencv` / `pillow` 做**传统特征**：颜色直方图、HOG、边缘密度、纹理（LBP）、连通域统计 → 接 LightGBM。**效果有限，但比没有强** |

### 4.2 开赛前的准备（现在就做）

1. **确认 GPU 那台机器能用**：跑通一个最小例子（比如加载一个预训练模型做一次推理），
   证明环境没问题。**别等 10-23 才发现装不上。**
2. 若拿不到 GPU，**在 D1 就接受"图像题只能做传统特征"**，把精力挪到论文和创新点上。

### 4.3 图像特有的坑

- 图片尺寸不统一 → 必须统一 resize
- 训练/测试图像来源不同（不同设备/光照）→ 又是一次"批次效应"，对抗验证会有用
- 数据量大（几万张图）→ 读图会成为瓶颈，用并行读

## 5. 多模态拼接

**按主表定类型，其余模态当特征。**

- 表格 + 文本 → 文本列用 TF-IDF 转成数值，和表格特征拼起来
- 表格 + 时间 → 按实体聚合时间序列的统计量
- 所有模态融合时，**注意每条数据的对齐口径**（一行表格对应多条文本/多个时间点，怎么聚合？）

> **融合策略的说法**：早期融合（拼特征）/ 晚期融合（各模单独建模再平均）/ 中间融合。
> 生信里的"多组学整合"就是这套东西，可以直接引用（见 [文献库.md](文献库.md) §1）。
